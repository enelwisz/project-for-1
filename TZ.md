
1. Техническое Задание (TZ.md)


1. Общие сведения

• Название проекта: CyberRunner AI — тактическая 2D-головоломка с автономным агентом.
• Цель проекта: Разработка десктопного игрового приложения на языке Python с использованием фреймворка PyQt6 и реляционной базы данных SQLite.
• Целевой объем кодовой базы: 550–750 строк кода (без учета комментариев и пустых строк).

2. Описание игровой механики

• Игровое поле представляет собой двумерную сетку (лабиринт), состоящую из проходимых клеток, непроходимых стен, точки старта и точки финиша.
• Управление агентом: Игрок не управляет роботом напрямую с помощью клавиатуры. Вместо этого игрок указывает целевую точку на игровом поле кликом левой кнопки мыши.
• Поиск пути: После клика автономный робот-агент рассчитывает кратчайший маршрут от текущей позиции до выбранной клетки с помощью алгоритма поиска пути (A* или BFS) и начинает плавное перемещение по нему.
• Противники: На карте присутствуют 3 вражеских патрульных бота, которые циклично и с повышенной скоростью двигаются по заранее заданным замкнутым маршрутам.
• Условия победы и поражения:
	• Победа: Робот достигает клетки финиша. Фиксируется время прохождения и количество совершенных кликов.
	• Поражение: Расстояние между центром робота и центром любого из вражеских ботов становится меньше критического (столкновение). Игра останавливается с предложением перезапустить уровень.

3. Функциональные требования

1. Графический интерфейс (GUI):
	• Главное окно с выбором уровня сложности (минимум 3 уникальные карты).
	• Игровое поле с плавной отрисовкой (60 FPS) спрайтов или векторной графики, а также визуализацией текущего маршрута робота.
	• Информационная панель: таймер текущей попытки, счетчик кликов (команд), кнопки «Старт/Рестарт» и «Таблица рекордов».
	• Стилизация интерфейса с помощью таблиц стилей QSS (темная неоновая тема).
2. База данных (SQLite):
	• Хранение конфигураций уровней (название, матрица карты, координаты старта, финиша и маршрутов патрульных ботов).
	• Хранение таблицы рекордов игроков (имя игрока, пройденный уровень, затраченное время в секундах, количество кликов, дата прохождения).
	• Автоматическая инициализация БД и заполнение базовыми уровнями при первом запуске программы.


4. Архитектура проекта

Проект реализован в виде монолитной однофайловой архитектуры для упрощения сборки, отладки и запуска. Вся программная логика, работа с базой данных, алгоритмы и графический интерфейс объединены в едином исполняемом файле main.py (~600–700 строк кода), логически разделенном на независимые классы:
• DatabaseManager — класс для работы с локальной базой данных SQLite (game_data.db): создание таблиц, загрузка базовых уровней и сохранение/чтение таблицы рекордов.
• Pathfinder — модуль алгоритма поиска кратчайшего пути (BFS / A*) по двумерной матрице карты.
• Agent и PatrolBot — классы игровых сущностей, отвечающие за координаты, скорость, плавное попиксельное перемещение и циклическое патрулирование.
• GameBoard(QWidget) — кастомный виджет игрового поля: игровой цикл (QTimer на 60 FPS), обработка кликов мыши, проверка столкновений и отрисовка графики/текстур через QPainter.
• MainWindow(QMainWindow) — главное окно приложения: верхняя панель управления (выбор уровня, таймер, счетчик кликов, кнопки перезапуска и рекордов) и встроенные QSS-стили оформления.
Структура папки проекта:
• main.py — основной файл программы (весь исходный код).
• game_data.db — файл базы данных SQLite (генерируется автоматически).
• assets/ — папка с графическими ресурсами (текстуры и спрайты .png).
• README.md, requirements.txt, .gitignore, TZ.md — документация и файлы репозитория.
